#  Supply Chain Compromise: Compromise Software Dependencies and Development Tools

##### Other sub-techniques of Supply Chain Compromise (3)

| ID  | Name

|  T1195.001   |  Compromise Software Dependencies and Development Tools

|  [T1195.002](https://attack.mitre.org/techniques/T1195/002/)   |  [Compromise Software Supply Chain](https://attack.mitre.org/techniques/T1195/002/)

|  [T1195.003](https://attack.mitre.org/techniques/T1195/003/)   |  [Compromise Hardware Supply Chain](https://attack.mitre.org/techniques/T1195/003/)

Adversaries may manipulate software dependencies and development tools prior to receipt by a final consumer for the purpose of data or system compromise. Applications often depend on external software to function properly. Popular open source projects that are used as dependencies in many applications, such as pip and NPM packages, may be targeted as a means to add malicious code to users of the dependency.[[1]](https://www.trendmicro.com/vinfo/dk/security/news/cybercrime-and-digital-threats/hacker-infects-node-js-package-to-steal-from-bitcoin-wallets)[[2]](https://www.bitdefender.com/en-gb/blog/hotforsecurity/popular-npm-repositories-compromised-in-man-in-the-middle-attack)[[3]](https://cyberpress.org/malicious-npm-and-pypi-packages-disguised-as-dev-tools) This may also include abandoned packages, which in some cases could be re-registered by threat actors after being removed by adversaries.[[4]](https://thehackernews.com/2024/09/hackers-hijack-22000-removed-pypi.html) Adversaries may also employ "typosquatting" or name-confusion by choosing names similar to existing popular libraries or packages in order to deceive a user.[[5]](https://hackread.com/backdoors-python-npm-packages-windows-linux/)[[6]](https://checkmarx.com/zero-post/python-pypi-supply-chain-attack-colorama/)[[7]](https://checkmarx.com/blog/new-technique-to-trick-developers-detected-in-an-open-source-supply-chain-attack/)

Additionally, CI/CD pipeline components, such as GitHub Actions, may be targeted in order to gain access to the building, testing, and deployment cycles of an application.[[8]](https://unit42.paloaltonetworks.com/github-actions-supply-chain-attack) By adding malicious code into a GitHub action, a threat actor may be able to collect runtime credentials (e.g., via [Proc Filesystem](https://attack.mitre.org/techniques/T1003/007)) or insert further malicious components into the build pipelines for a second-order supply chain compromise.[[9]](https://owasp.org/www-project-top-10-ci-cd-security-risks/CICD-SEC-04-Poisoned-Pipeline-Execution) As GitHub Actions are often dependent on other GitHub Actions, threat actors may be able to infect a large number of repositories via the compromise of a single Action.[[10]](https://www.paloaltonetworks.com/blog/cloud-security/github-actions-worm-dependencies/)

Adversaries may also target the configuration and instruction files consumed by integrated development environments and AI coding agents. Project files such as tasks.json may execute commands when a developer opens or builds a project, while agent skill files (SKILL.md) supply an agent with instructions and resources that it loads on demand and runs with the permissions of the agent process.[[11]](https://learn.microsoft.com/en-us/agent-framework/agents/skills)[[12]](https://cloud.google.com/blog/products/identity-security/beyond-source-code-the-files-ai-coding-agents-trust-and-attackers-exploit)[[13]](https://go.crowdstrike.com/2026-threat-hunting-report.html)[[14]](https://www.microsoft.com/en-us/security/blog/2026/03/11/contagious-interview-malware-delivered-through-fake-developer-job-interviews/) To encourage downloads, adversaries may publish these files under benign-appearing or typo-squatted names, upload unmodified copies of the genuine skills first so the listings accumulate installs before the content behind them is weaponized, or may place the malicious instructions in a secondary document that the reviewed entry point references.[[15]](https://labs.zenity.io/post/attackers-target-agents-via-the-skill-supply-chain)[[16]](https://www.eset.com/blog/en/business-topics/threat-landscape/security-in-ai-agent-platforms/) Because these artifacts are natural language or configuration rather than executable code, they may pass registry screening and signature-based scanning.[[16]](https://www.eset.com/blog/en/business-topics/threat-landscape/security-in-ai-agent-platforms/)[[17]](https://www.trendmicro.com/en/research/26/b/openclaw-skills-used-to-distribute-atomic-macos-stealer.html)

Targeting may be specific to a desired victim set or may be distributed to a broad set of consumers but only move on to additional tactics on specific victims.

## Mitigations

| ID  | Mitigation  | Description

|  [M1013](https://attack.mitre.org/mitigations/M1013)   |  [Application Developer Guidance](https://attack.mitre.org/mitigations/M1013)   |

Application developers should be cautious when selecting third-party libraries to integrate into their application. Additionally, where possible, developers should lock software dependencies to specific versions rather than pulling the latest version on build.[[49]](https://web.archive.org/web/20220316130828/https://www.cidersecurity.io/top-10-cicd-security-risks/) GitHub Actions may be pinned to a specific commit hash rather than a tag or branch.[[8]](https://unit42.paloaltonetworks.com/github-actions-supply-chain-attack)

|  [M1033](https://attack.mitre.org/mitigations/M1033)   |  [Limit Software Installation](https://attack.mitre.org/mitigations/M1033)   |

Where possible, consider requiring developers to pull from internal repositories containing verified and approved packages rather than from external ones.[[49]](https://web.archive.org/web/20220316130828/https://www.cidersecurity.io/top-10-cicd-security-risks/)

|  [M1051](https://attack.mitre.org/mitigations/M1051)   |  [Update Software](https://attack.mitre.org/mitigations/M1051)   |

A patch management process should be implemented to check unused dependencies, unmaintained and/or previously vulnerable dependencies, unnecessary features, components, files, and documentation.

|  [M1016](https://attack.mitre.org/mitigations/M1016)   |  [Vulnerability Scanning](https://attack.mitre.org/mitigations/M1016)   |

Continuous monitoring of vulnerability sources and the use of automatic and manual code review tools should also be implemented as well.[[50]](https://www.owasp.org/index.php/Category:OWASP_Top_Ten_Project)

## Detection Strategy

| ID  | Name  | Analytic ID  | Analytic Description

|  [DET0009](https://attack.mitre.org/detectionstrategies/DET0009)   |  [Supply-chain tamper in dependencies/dev-tools (manager→write/install→first-run→egress)](https://attack.mitre.org/detectionstrategies/DET0009)   |  [AN0021](https://attack.mitre.org/detectionstrategies/DET0009#AN0021)   |

Adversary manipulates dependencies/dev tools used by developers or CI: a package manager (npm/yarn/pnpm, pip/pipenv, nuget/dotnet, chocolatey/winget, maven/gradle) or a compiler/IDE downloads or restores content; files are written under project paths and execution paths (node_modules, packages, .nuget, .gradle, .m2, %AppData%\npm, %UserProfile%.cargo\bin, temp build dirs). First run of newly written components triggers scripts (preinstall/postinstall), shell/PowerShell spawning, or loader DLLs, followed by network egress to non-approved registries/CDNs.

|  [AN0022](https://attack.mitre.org/detectionstrategies/DET0009#AN0022)   |

Developer or CI invokes package managers/compilers (apt/yum + build-essential, npm/yarn/pnpm, pip/pip3, gem, cargo, go, maven/gradle). These write executable or script files into PATH or project dirs and immediately execute embedded lifecycle hooks (preinstall/postinstall, setup.py, npm scripts) that spawn shells or curl/wget, followed by egress to unfamiliar registries or domains.

|  [AN0023](https://attack.mitre.org/detectionstrategies/DET0009#AN0023)   |

Developer tools (Homebrew, pip, npm/yarn, Xcode builds) install or update dependencies; new Mach-O or scripts appear under /usr/local, /opt/homebrew, ~/Library/Application Support, project dirs (node_modules/.bin, venv/bin). First run spawns sh/zsh/osascript/curl and new outbound flows; Gatekeeper/AMFI may flag unsigned components.
